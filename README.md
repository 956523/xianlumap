# 线路图

给自驾线路做一张**打开就能用**的规划地图。

一条线路一页，打开即全量数据：路线轨迹、海拔剖面、补能点（充电站 + 加油站）、
途经城镇与景点、逐日行程卡。不需要登录，不需要联网搜索，不需要点按钮等它加载。

> **当前状态**：第一条线路「青甘大环线」可用（S0 缩放分级已完成）。
> 平台化改造进行中，目标是让这套框架能服务**任意自驾线路**。

## 打开看看

直接双击 `index.html` 即可（需联网加载腾讯地图底图）。

## 第一条线路：青甘大环线

**西宁 / 兰州出发 · 顺时针方向 · 全程约 3784 km · 建议 9–10 天**

| 指标 | 数值 |
| ---- | ---- |
| 总里程 | 2164 km（单程主线，不含回程重复段） |
| 建议天数 | 9 天 |
| 最高海拔 | 3794 m |
| 充电站点 | 282 个（沿线里程网格筛选后显示） |
| 加油站点 | 193 个 |

路线覆盖：西宁 → 青海湖 → 茶卡 → 德令哈 → 大柴旦 → 敦煌 → 嘉峪关 → 张掖 → 祁连 → 门源 → 兰州。
另含一条「经典支线」（塔尔寺—拉脊山）。

**两条已知的数据边界**（不掩饰，页面上也标）：

- 德令哈 → 阿克塞一段约 476 km 无充电站 —— 这是**腾讯 POI 接口的能力上限**
  （`region()` 边界只覆盖行政区建成区，看不见高速走廊），不是我们没抓
- 充电**枪数**拿不到 —— 腾讯、高德开放 API 均不提供，运营商裸接口无法打通。
  这个字段已从本轮需求中降级移除

### 两条设计约定

**一、路线固定 = 数据固定。**
路线不会变，所以补能点数据在**构建时一次性抓全、固化进页面**。打开即全量，
不做"点按钮实时搜索"—— 那是把等待时间推给用户。

**二、抓不到的，不许假装抓到。**
数据缺口在页面上如实标出，不做人工补数据（那是把活儿推给用户）。
构建时跑四类体检（物理合理性 / 补给覆盖 / 投影自洽 / 里程对账），结果透出给用户。

## 技术说明

- **地图**：腾讯地图 GL JS（代理模式，无需 API Key）
- **构建**：纯 Node，零第三方依赖
- **页面**：单 HTML 文件，零构建工具链 —— 改完刷新即可看到效果

### 已知的接口限制（实测结论，非猜测）

| 探测方式 | 结果 |
| ---- | ---- |
| `boundary=region(西宁市,0)` | ✅ count=486 |
| `boundary=rectangle(...)` | ❌ count=0 |
| `boundary=nearby(...)` | ❌ count=0 |
| `boundary=polygon(...)` | ❌ status=348 参数不合法 |

`region()` 只覆盖行政区建成区 —— **它天生看不见高速公路走廊、看不见无人区**。
这是青甘线上"476km 无桩"的真实原因。
